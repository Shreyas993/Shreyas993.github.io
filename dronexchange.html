Project Overview

This engagement involved a structured penetration test of a drone marketplace application across six sprints. Testing covered authentication, session management, access control, payment and order workflows, file uploads, storage, and cloud configuration.

The team used manual testing, direct HTTP request manipulation, application behaviour analysis, and cloud configuration review to identify security weaknesses, document risks, and verify remediation.

Testing was conducted in a designated test environment using test accounts and payment transactions in Stripe test mode.

My Role & Responsibilities

As Security Lead and Test Coordinator, I led the security workstream of a five-person team and coordinated testing activities throughout the engagement.

  • Defined testing scope and rules of engagement.
  • Contributed to threat modelling and asset mapping.
  • Maintained the project risk register.
  • Raised findings as GitHub issues and tracked remediation.
  • Performed hands-on security testing and retesting.
  • Coordinated sprint progress and stakeholder updates.
  • Contributed to the final report and remediation roadmap.

Testing Methodology & Scope

The engagement combined manual penetration testing, API request analysis, payment workflow validation, source-level investigation, and cloud configuration review. With authorised access to the designated test environment, including an administrative test account, the team examined application behaviour and relevant backend and cloud security controls. Testing was organised across six sprints, with findings documented, prioritised, and followed through remediation and retesting.

Authentication & Access Control

Assessed authentication and session behaviour, role-based permissions, and server-side authorisation boundaries. Used authorised test accounts and HTTP requests to examine whether access restrictions were correctly enforced.

Payment & Business Logic

Examined payment and order workflows, payment verification, webhook handling, and controls around sensitive payment-related actions. Used Stripe CLI to support investigation of payment integration behaviour in the test setup.

File Upload Security

Evaluated file-upload validation, file handling, storage access, and path-related risks. Examined relevant upload workflows and supported retesting to verify remediation.

Cloud Configuration & Permissions

Reviewed authorised cloud resources and relevant configuration using the access granted for the test environment. Examined storage permissions, service-account access, and security settings for potential misconfiguration and excessive privileges.

API & HTTP Testing

Used Postman and Burp Suite to inspect and manipulate HTTP requests, examine API responses, and assess how the application handled unexpected inputs and security-sensitive actions. Browser developer tools provided additional visibility into client-side behaviour.

Firebase, Firestore & Data Handling

Investigated the local development environment and reviewed relevant Firebase and Firestore implementation details to understand data handling, application logic, and the security controls governing access to application data.

Retesting & Risk Tracking

Documented findings, maintained the risk register, tracked remediation through GitHub issues, and supported verification of fixes. Retesting helped establish the recorded status of findings at the conclusion of the engagement.

Payment Integrity

A critical finding involved the ability to manipulate an order's payment status without a genuine, verified payment. Remediation strengthened server-side payment verification, and the finding was subsequently retested.

Access Control & Permissions

Testing examined authorisation boundaries for privileged actions and sensitive resources. Reported permission and access-control concerns were tracked through remediation.

Payment Integration Security

The team assessed payment integration controls, including Stripe webhook signature verification and sensitive payment-related workflows.

File Privacy & Storage

File-handling and storage reviews identified concerns requiring remediation, including GPS metadata exposure in uploaded images and permissions affecting stored resources.

Final Retest Outcome

At engagement close, all 18 risk-register findings were recorded as mitigated following remediation and retesting. The final report recorded zero open risk-register findings.

Technical Lessons Learned

Trust Server-Side Controls

Security-sensitive operations must be validated on the server rather than relying on client-side state or submitted request values.

Verify Payment State

Payment and order workflows need reliable server-side verification so that an order cannot be treated as paid without a valid payment confirmation.

Consider Data Privacy

File security extends beyond upload validation. Metadata and storage permissions can also create privacy and information-exposure risks.

Retest After Remediation

A reported fix should be verified against the original issue. Tracking remediation and recording retest results help establish the final status of findings.
